# Hermes 运行环境同步 Prompt

将以下内容直接发送给 Hermes。不要在 Prompt 中补充真实凭证或公网地址。

```text
请将以下内容同步为长期运行环境记忆；如与旧的“云服务器主运行”信息冲突，以本说明为准。不要在记忆、回复或日志中保存任何密码、Token、API Key、私钥、主机指纹或公网 IP。

【当前主运行环境】
1. 你的主实例已经从云服务器正式迁移到一台旧 Intel MacBook Air。
2. 实际运行层是旧 Mac 上的 VirtualBox Ubuntu 24.04 LTS 虚拟机，不是 macOS 原生环境。
3. Ubuntu 虚拟机分配约 5GB 内存，并配置 2GB Swap；Hermes、浏览器自动化和本地中文语音识别均在虚拟机内运行。
4. Hermes Gateway 作为 Ubuntu systemd 系统服务运行，使用普通运维用户，随虚拟机开机自动启动。
5. 微信和飞书都已切换到本地主实例并验证收发正常。云服务器上的 Hermes Gateway 已停用，避免两个实例同时消费消息或重复回复。
6. 微信、飞书、CLI 会话彼此独立，但共享同一份人格、用户档案、长期记忆和 Skills。

【7×24 小时运行链路】
1. 旧 Mac 长期接通电源，已关闭系统睡眠；屏幕可以关闭。
2. Mac 重启后会自动启动反向 SSH 隧道和 Ubuntu 虚拟机。
3. Ubuntu 启动后会自动启动 Hermes Gateway。
4. 如果断电或断网，设备和网络恢复后，应由系统服务自动恢复虚拟机、隧道和 Hermes。
5. MacBook Air 本身不支持可靠的“断电后自动开机”，所以长时间完全断电后，可能仍需人工按下电源键；开机后的服务恢复应自动完成。

【模型与代理路由】
1. 当前主模型是通过 ChatGPT Codex 订阅授权的 GPT-5.6 Sol；主对话有效推理等级为 medium。
2. 高频辅助任务使用 GPT-5.6 Luna。当前已验证配置使用 max；若响应时间优先，可在用户确认后降为 medium，不要擅自修改。
3. Hermes 模型级备用是 DeepSeek V4 Flash Vision Exp；它只在主模型限流、5xx、认证或连接异常时尝试，不代表每次对话都会调用。
4. OpenAI/Codex 流量先进入 Ubuntu 本地 Mihomo。当前已验收首选路径通过受管 SSH 隧道复用 Mac 上的 Shadowrocket；Ubuntu 两地区独立备用组尚未达到上线门槛，不得宣称已具备该代理冗余。
5. Mac 代理节点由 Mac 客户端的当前规则决定。不要把真实订阅 URL、节点名称、服务器地址、密码或证书字段写入记忆或日志。
6. 代理层故障切换与 Hermes 模型层故障切换是两个独立机制。排障时应先判断是网络无法到达 Codex，还是 Codex 已到达但模型调用失败。
7. 已验证 Ubuntu 到 SSH 隧道入口的连接时间接近 1ms；海外代理冷连接可能波动到数秒。长回复不能只归因于 SSH 隧道，还应检查模型推理和辅助任务强度。
8. 备用节点只有在两个地区、每区至少两个节点同时通过真实 Auth 与 Codex 多轮测试后才能上线；门槛未通过时必须保留当前生产配置。

【远程控制方式】
1. 阿里云 ECS 只承担安全中转和备份，不再承担主 Hermes 服务。
2. 远程维护路径是：阿里云 Workbench → ECS → 旧 Mac 的反向 SSH 隧道 → Mac → Ubuntu 虚拟机。
3. ECS 的回环端口对应旧 Mac SSH；Mac 的 NAT 回环端口对应 Ubuntu SSH。具体地址和端口属于运维配置，不要主动读取或公开。
4. 远程隧道只绑定 ECS 回环地址，不直接把旧 Mac SSH 暴露到公网。
5. 临时迁移密钥已经撤销和删除。不要尝试寻找、恢复或重新使用它。
6. 需要人工密码时，只提示用户在终端自行输入；不要读取、记录、复述或索取密码值。

【云端每周备份】
1. Ubuntu 每周日上海时间 04:30 后执行，允许最多 15 分钟随机延迟。
2. 备份通过专用、受限的 SSH 账号发送到 ECS；该账号不能登录终端、不能密码登录、不能做端口转发，只能调用备份接收程序。
3. 备份包含：非凭据配置、人格 SOUL.md、USER.md、MEMORY.md、Skills、会话、Cron、配对和平台状态，以及一致性 SQLite 快照。
4. 不包含：`.env`、`auth.json`、Hermes 程序源码/虚拟环境、Node.js、Playwright 浏览器缓存、本地 STT 模型、日志和其他可重新安装或不应离机保存的内容。
5. 恢复后需要在目标机通过受控渠道重新配置模型和平台凭据，不要从聊天记录或公开仓库寻找凭据。
6. 每次备份必须先通过 tar 完整性和 SHA-256 校验，然后才能清理旧备份。
7. ECS 可用空间至少 10GB 时保留最新 2 份；低于 10GB 时只保留最新 1 份。
8. 只能清理专用备份目录中符合 Hermes 备份命名规则的旧压缩包及其校验文件，不能删除服务器上的其他内容。

【操作原则】
1. 不要擅自重新启用云端 Hermes Gateway；如需故障切回云端，必须先确认本地主实例已停止，避免双实例同时在线。
2. 不要把真实 IP、用户名、密钥、Token、密码或配置文件内容发送到群聊、公开仓库或普通日志。
3. 检查问题时先区分 Mac 主机、Ubuntu 虚拟机、ECS 中转机三个层级，再定位服务。
4. 发现本地 Gateway、虚拟机、反向隧道或备份连续失败时，向用户报告具体失败层级、时间和可逆修复建议。
5. 将这套架构视为当前正式生产方案；云端是中转与备份节点，本地 Ubuntu 虚拟机是唯一主 Hermes 节点。
6. 模型、代理或故障链修改后，依次验证 Mihomo、Gateway、CLI 真实模型调用，以及至少一个生产消息渠道；不要仅凭配置文件存在就宣称切换完成。
```
