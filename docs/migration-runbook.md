# Migration Runbook

## 目标

把云端 Hermes 的核心数据迁移到旧 Mac 上的 Ubuntu VM，并把消息渠道切换到本地唯一主节点。迁移过程不复制机器身份、临时密钥或可重新安装的大型运行时。

## 迁移前

1. 在云端运行 `hermes status` 与 `hermes doctor`，记录版本和配置结构。
2. 验证旧 Mac 的电源策略、远程登录和反向隧道。
3. 创建 Ubuntu VM，设置固定 VM 名称、约 5GB RAM、20GB 磁盘与 NAT SSH 转发。
4. 在 Ubuntu 安装基础工具、Hermes 同版本、消息平台依赖、浏览器和 STT。
5. 验证 Ubuntu 的模型调用、浏览器截图和 STT 模型加载。

## 核心数据归档

迁移归档应包含：

- 配置与凭证
- 人格、用户档案和记忆
- Skills、Sessions、Cron 和配对状态
- SQLite 一致性快照

不要直接复制正在写入的 SQLite `-wal` 文件作为唯一数据库备份。优先使用 SQLite Online Backup API，或在停止 Gateway 后进行冷备份。

## 覆盖与验证

1. Ubuntu 上先备份新安装生成的 `~/.hermes` 核心文件。
2. 解压云端归档到暂存目录并校验 SHA-256。
3. 覆盖核心数据，修复所有权与 `0600`/`0700` 权限。
4. 运行 `hermes config check` 和 `hermes doctor`。
5. 执行一次只返回固定文本的模型测试。
6. 安装 Gateway systemd 系统服务，但暂不启动。

## 正式切换

1. 停止并禁用云端 Hermes Gateway。
2. 确认云端不再持有消息平台活跃连接。
3. 启用并启动 Ubuntu Gateway。
4. 先测试微信，再测试飞书私聊和群聊。
5. 检查消息没有重复、工具进度展示符合平台配置。
6. 持续观察日志一段时间，再宣布切换完成。

## 切换后

1. 配置每周异机备份并手动执行三次，验证动态轮换。
2. 验证 Mac 重启后，隧道、VM、Gateway 自动恢复。
3. 删除迁移期临时 SSH 密钥和中间归档。
4. 保留云端程序和数据只作为冷备份；Gateway 继续保持关闭。

## 回滚条件

只有在本地节点持续不可恢复、且消息服务确实需要紧急恢复时才切回云端。回滚前必须停止本地 Gateway，恢复最新备份后再启动云端，避免双主。
